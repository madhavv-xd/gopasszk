# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`gopasszk`: a zero-knowledge password manager. It has a Gin + GORM/Postgres API server (`cmd/server`) and a terminal client (`cmd/gopass`). The server only ever stores an auth hash and ciphertext. It never sees the master password or the encryption key.

## Commands

All config comes from a `.env` at the repo root (gitignored). `config.LoadConfig` finds it by walking up from the cwd, so tests run from package dirs still pick it up. Required vars: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `SALT_HMAC_SECRET`, `JWT_SECRET`. The DB host is hardcoded to `localhost:5432`.

```sh
docker compose up -d                 # Postgres 16, reads the same .env
go run ./cmd/migrate                 # GORM AutoMigrate for User + Credential (the only schema mechanism)
go run ./cmd/dbtest                  # connectivity/ping check
go run ./cmd/server                  # API on :8080, Swagger UI at /swagger/index.html
go build -o gopass.exe ./cmd/gopass  # CLI: register | login | add | list | edit <id> | delete <id>
                                     # GOPASS_SERVER overrides http://localhost:8080

go test ./...                                        # full suite (needs Postgres up + migrated)
go test ./internal/crypto -run TestEncryptDecryptRoundTrip   # single test
go vet ./...

swag init -g cmd/server/main.go      # regenerate docs/ after changing any godoc @ annotations
```

Tests in `internal/handlers`, `internal/repository`, and `internal/auth` (`salt_test.go`) connect to the real Postgres and create and delete rows with fixed emails. Tests in `internal/crypto`, plus `jwt_test.go` and `hash_test.go`, are pure. `docs/` is generated by swag, so don't hand-edit it.

## Crypto / auth flow (spans `internal/crypto`, `internal/auth`, `internal/handlers`, `cmd/gopass`)

- **Client side** (`internal/crypto`, used by `cmd/gopass`): the client generates a random 16-byte salt per user. It then derives two independent 32-byte Argon2id keys from the master password, using `salt || "auth"` and `salt || "enc"`:
  - `DeriveAuthHash` produces the auth hash, which is sent to the server.
  - `DeriveEncryptionKey` produces the AES-256-GCM key, which never leaves the client.
- **Server side**: the incoming 32-byte auth hash is hashed *again* with Argon2id (`auth.HashAuthKey`, stored as a PHC string) before storage. Login verifies it with `auth.VerifyAuthKey` and issues an HS256 JWT (24h) with a `user_id` claim.
- **Ciphertext wire format** (username and password fields): `base64(nonce[12] || GCM ciphertext+tag)`. Two things depend on this layout:
  - `cmd/gopass/vault.go` builds and parses it.
  - `handlers.validateCipherText` only checks the decoded length (28–4096 bytes). The server never decrypts.
- **Anti-enumeration**: keep both of these when you touch auth.
  - `GET /salt` for an unknown email returns `HMAC-SHA256(SALT_HMAC_SECRET, email)[:16]`, a deterministic fake salt.
  - `POST /login` for an unknown email still runs the Argon2 verify against `dummyHash` and returns the same 401.
- **CLI session**: login saves `{email, token}` to `os.UserConfigDir()/gopass/session.json`. Every vault command except `delete` calls `unlock()`, which re-prompts for the master password, re-logs in for a fresh token, and derives the encryption key.

## Server layering and ownership

- `cmd/server/main.go` wires the routes. Handlers are methods on `handlers.Handler`, which holds `DB`, `Secret` (salt HMAC key), and `JWTSecret`.
- `repository` is plain functions that take `*gorm.DB`. There are no interfaces.
- `middleware.RequireAuth` validates the Bearer JWT and sets `c.Set("userID", ...)`. The credential owner always comes from that value, never from the request body.
- Every credential repository query is scoped by `id AND user_id`. When zero rows are affected, it returns `gorm.ErrRecordNotFound`, and handlers map that to 404. Accessing another user's row therefore looks the same as a missing row. `TestCrossUserCredentialAccess` guards this.
- The DB is opened with `TranslateError: true`, so a duplicate email surfaces as `gorm.ErrDuplicatedKey` and is mapped to 409.
- There is no `ON DELETE CASCADE` on `credentials.user_id`. Delete a user's credentials before deleting the user (tests rely on defer ordering for this).
- New models must be added to the `AutoMigrate` call in `cmd/migrate/main.go`.
